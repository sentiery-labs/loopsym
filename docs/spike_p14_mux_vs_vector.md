# [CLD-P14] 스파이크: Mux/Demux vs 벡터 신호 — 설계 비교와 권고

> 결정은 사람(충박사). 이 문서는 판단 재료 + 동작하는 프로토타입 결과.

## 배경
14~15주차(쿼드로터 1축→3축)와 P4(실기체: 자세 3축, 속도 3축)는 다채널 신호가
필요하다. 두 노선이 있다:

## 노선 A — Mux/Demux 블록 (스칼라 와이어 유지) ★프로토타입 구현됨
와이어는 계속 "값 하나"를 나른다. 단 그 값이 튜플일 수 있고, 튜플은
Mux 가 만들고 Demux 만 소비한다 (v1 규칙: 연산 블록 투입 금지).

- 장점: 엔진 무변경(이미 동작 — `test_mux_demux_roundtrip` green). 학생이 배우는
  모델이 단순("와이어 = 값 하나"). Simulink 의 Mux 개념과 대응.
- 단점: 3축 PID 를 만들려면 Demux → 스칼라 3벌 → Mux 로 펼쳐야 한다 (다이어그램이
  커진다 — 교육적으로는 오히려 장점일 수도: 축 3개가 눈에 보인다).
- 프로토타입: `Mux`/`Demux` 블록 (loopsym/blocks.py), 파이썬·뷰어 양쪽 구현,
  Scope 직결 시 친절한 에러("Demux 로 풀어서 연결").

## 노선 B — 진짜 벡터 신호 (와이어가 ndarray 를 나름)
Gain·Sum 이 요소별 연산으로 벡터를 그대로 통과시키는 Simulink 방식.

- 장점: 3축 제어기가 블록 1벌로 끝난다. 실무 Simulink 감각과 동일.
- 단점: **전 블록의 차원 전파(dimension propagation) 필요** — Integrator 상태
  크기가 입력 차원에 의존, Scope 채널 수 동적, 뷰어 JS 도 전부 재작업.
  대수 루프/feedthrough 분석은 무관하지만 엔진 코어가 "교육용 몇백 줄" 규모를
  벗어나기 시작한다. 오류 메시지 품질 확보도 일이 크다.

## 권고 (구현자 의견)
**v1 은 노선 A 유지 + 15주 커리큘럼도 A 로 설계.**
- 근거 1: 커리큘럼 목표는 "원리가 보이는 것" — 축이 펼쳐져 보이는 게 수업에 유리.
- 근거 2: P4 실기체 블록(Bebop/ROS2)은 포트를 축별 스칼라(roll/pitch/yaw/vz)로
  정의하면 벡터가 아예 필요 없다.
- 근거 3: 노선 B 는 되돌리기 어려운 코어 확장 — 베타 피드백(수강생이 실제로
  불편해하는지) 확인 후 v2 에서 결정해도 늦지 않다.
- 부속 제안: 3축 편의는 "서브시스템 복제 + 마스크(P12)"로 해결 가능
  (같은 PID 서브시스템을 axis 별 params 로 3개).
