#### 반복된 실패: ex11 결과 플롯

재현 조건은 다음과 같다.

1. `python3 examples/ex11_px4_sitl.py`가 exit 0과 수치 PASS를 출력한다.
2. 마지막에 출력된 `examples/ex11_diagram.html`을 Browser(Pyodide)로 연다.
3. 하단은 `▶ 실행을 누르면 Scope 파형이 여기에 표시됩니다.`이고
   `lastScopes`는 `null`이다.
4. ▶ 실행을 누르면 약 0.716~0.729초 뒤
   `MavlinkHil 블록은 pymavlink 가 필요합니다 ... Pyodide 브라우저 모드 불가`
   오류가 난다.

ex11은 실행이 끝난 뒤 `render_html()`로 다이어그램만 직렬화한다
([`examples/ex11_px4_sitl.py:65-67`](../../examples/ex11_px4_sitl.py#L65)).
`render_html()`도 모델 JSON과 엔진 소스만 넣고 이미 수집한 Scope 표본은 넣지
않는다([`loopsym/viz.py:243-272`](../../loopsym/viz.py#L243)). 뷰어의 초기 Scope
영역도 실행 전 자리표시자다
([`loopsym/viewer.html:345-347`](../../loopsym/viewer.html#L345)). 따라서 콘솔의
수치 판정은 재현됐지만, 시나리오에 적힌 **방금 비행의 결과 플롯 확인**은 다섯
회차 모두 성립하지 않았다.

### B-2. 실제 침묵 구간

ex11의 비어 있지 않은 콘솔 줄 사이 wall-clock 간격을 다섯 회에서 측정했다.

| 구간 | 무출력 시간 범위 | 직전/직후 출력 | 화면이 설명하는 상태 |

`0 / 0 / 0`은 `px4` 프로세스 / TCP 4560 / UDP 18570 순이다. 모든 회차에서
실행 전에는 셋 다 비었고, 실행 중에는 셋 다 관측됐으며, 종료 직후 첫
표본에서 다시 비었다. 재실행 실패나 정리 재시도는 없었다.

실제 기동 배너는 다음 형식이었다.

```text
[PX4] 기동 — 실 SITL 바이너리 /home/sentiary/PX4-Autopilot/build/px4_sitl_default/bin/px4 (PID ...), 펌웨어 v1.16.0
```

바이너리 경로와 태그는 보였지만 PX4 HEAD 해시는 5회 모두 없었다. EKF 줄은
`EKF 정렬 대기 t=5s / 20s`부터 t=20s까지 진행 시간을 알렸을 뿐 estimator
상태나 수렴 판정값은 출력하지 않았다. 고도는 t=21s `-0.00m`에서 t=24s
`0.28m`, t=25s `1.09m`, t=60s `2.51m`로 상승·유지를 화면에서 확인할 수
있었다. 마지막 요약은 lockstep 계산 완료를 문맥상 나타냈지만 문자열 `종료`는
5회 모두 없었다. 따라서 “바이너리/해시”와 명시적 “lockstep 종료 줄”을 문자
그대로 적용하면 R3 전체는 부분 통과다.

### D-5. B-2 침묵 네 구간 재측정

원 감사와 같은 경계 구간을 유지하되, 이번에는 경계 사이의 새 로그를 포함한
**총 구간 길이**와 비어 있지 않은 PTY 출력 줄 사이의 **최장 연속 무출력**을
분리해 측정했다.

| 구간 | 원 감사 총 무출력 | 이번 총 구간 | 중간 진행 출력 | 이번 최장 연속 무출력 | 재판정 |

유일하게 1초를 넘는 연속 침묵으로 남았다.
