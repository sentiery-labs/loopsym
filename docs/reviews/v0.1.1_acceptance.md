## Codex 재검증 상세

### 실행 환경과 명령 해석

- Python `3.10.12`, Google Chrome `147.0.7727.55`, Node `20.20.2`
- 이 호스트에는 unversioned `python` 명령이 없다. 문서의 정확한
  `python tools/check_wheel.py`도 `/bin/bash: python: command not found`로
  종료되는 것을 먼저 확인했다. 이후 같은 인터프리터의 실제 명령인 `python3`로
  재실행했다. 새 venv 내부 검증은 venv의 `bin/python`을 사용했다.
- 전체 회귀는 `python3 -m pytest tests/ -q`로 재실행해
  `102 passed in 36.46s`를 확인했다.

### 실패 재현 #1 — 공개 PyPI 설치

저장소 밖의 새 venv에서 공개 인덱스만 사용했다.

```bash
python3 -m venv /tmp/loopsym-accept-pypi/venv
/tmp/loopsym-accept-pypi/venv/bin/python -m pip install loopsym
/tmp/loopsym-accept-pypi/venv/bin/loopsym --help
/tmp/loopsym-accept-pypi/venv/bin/python -m loopsym --help
```

관찰 출력:

```text
Using cached loopsym-0.1.0-py3-none-any.whl
Successfully installed loopsym-0.1.0
/tmp/loopsym-accept-pypi/venv/bin/loopsym: No such file or directory
No module named loopsym.__main__; 'loopsym' is a package and cannot be directly executed
```

대조군으로 `python3 tools/check_wheel.py`는 로컬 `dist/loopsym-0.1.1-...whl`에
대해 통과했다. 즉 구현 산출물은 준비됐지만 기준에 적힌 공개 설치 경로는 아직
0.1.1을 전달하지 않는다.

### 실패 재현 #4 — 오프라인 복구 명령

로컬 0.1.1 wheel의 번들 PI를 HTML로 렌더한 뒤, 새 Chrome 프로필에서 CDP
`Network.setCacheDisabled(cacheDisabled=true)`와
`Network.emulateNetworkConditions(offline=true, throughput=0)`를 적용했다.
실행 직전 브라우저 값은 다음과 같았다.

```json
{"online":false,"mode":"Browser (Pyodide)","status":""}
```

CDP `Runtime.evaluate`로 `btnRun.click()`을 실행한 지 0.25초 뒤 상태줄은 다음을
표시했다.

```text
Pyodide 로드 실패 — 첫 실행은 인터넷(CDN)이 필요합니다. 오프라인이면 터미널에서
`python -m loopsym.server` 를 실행한 뒤 이 페이지를 새로고침하세요
(Local Server 모드로 전환됩니다).
```

그 명령을 core-only 0.1.1 wheel venv에서 그대로 실행했다.

```bash
/tmp/loopsym-accept-local/venv/bin/python -m loopsym.server
```

```text
ModuleNotFoundError: No module named 'fastapi'
```

복구를 유효하게 만들려면 상태줄이 server extra 설치까지 안내하거나, core 설치만으로
동작하는 복구 경로를 제시해야 한다. 현재 메시지는 실패 원인은 설명하지만 수용 기준의
“유효한 복구 명령”은 충족하지 못한다.

없어서 문서 경로 전체는 실패한다.

### 실브라우저 근거 #2, #3, #8

로컬 wheel만 설치한 venv에서 번들 PI를 렌더했다.

```bash
/tmp/loopsym-accept-local/venv/bin/python -c \
  "from loopsym.__main__ import _load_bundled; from loopsym import load_json,render_html; render_html(load_json(_load_bundled('pi')), '/tmp/loopsym-accept-pi.html', t_end=10.0, dt=0.01)"
google-chrome --headless --disable-gpu --no-sandbox --disable-extensions \
  --window-size=1024,768 --remote-debugging-port=9341 \
  --user-data-dir=/tmp/loopsym-accept-chrome-online \
  file:///tmp/loopsym-accept-pi.html
```

CDP `Runtime.evaluate`로 초기 DOM, `btnRun.click()`, 완료 후 Scope DOM을 읽었다.

```json
{"inner":[1024,629],"mode":"Browser (Pyodide)","blocks":5,
 "blockNames":["ref","err","PI_ctrl","plant","scope"],
 "overlaps":{"run_palette":false,"palette_canvas":false,
             "canvas_inspector":false,"bar_main":false},
 "bodyScroll":[1024,629]}
```

```json
{"status":"완료 — 1000 steps, RK4 (파이썬 엔진), dt=0.01",
 "cls":"ok","cards":1,"legends":["ref","y"],
 "scopeNames":["scope"],"canvases":[{"w":992,"h":190}]}
```

완료까지 실측은 1.43초였다. 자동화 값과 별도로 1024px 온라인 완료 화면 및 오프라인
장문 오류 화면을 실제 캡처해 육안으로도 패널/버튼 겹침이 없음을 확인했다.
