## (구) 최초 스파이크 (2026-07-13) — 판정 근거로 사용 금지

## 질문
파이썬 벽시계 루프로 실기체 상위 제어(25~50Hz)가 가능한가?

## 방법
`spikes/p40_realtime_spike.py` — sleep-until(절대시각) + 마지막 1ms 스핀 대기
스케줄러로 이산 PI 워크로드를 돌리며 데드라인 오차 측정. (개발 데스크톱, 유휴 상태)

## 결과

| rate | ticks | p50 | p95 | p99 | max | 판정 |
|------|-------|-----|-----|-----|-----|------|
| 50 Hz | 250 | 0.001 ms | 0.001 ms | 0.002 ms | 0.002 ms | PASS |
| 100 Hz | 500 | 0.001 ms | 0.001 ms | 0.001 ms | 0.002 ms | PASS |
| 250 Hz | 1000 | 0.000 ms | 0.001 ms | 0.001 ms | 0.001 ms | PASS |

## 결론
1. **타당함.** 유휴 데스크톱 기준 250Hz 까지도 지터가 판정 기준(p95<2ms)의
   1/1000 수준. Bebop(25Hz)·터틀봇(50Hz)급 상위 루프는 여유가 크다.
2. 지터의 핵심은 `sleep(전체)` 가 아니라 **sleep-until + 잔여 1ms 스핀** 패턴.
   P42 정식 구현에 이 스케줄러를 그대로 쓴다.
3. 남은 리스크는 스케줄러가 아니라 **I/O 블로킹** (WiFi 송수신, ROS2 콜백).
   → P42 에서 소스/싱크는 비동기(별도 스레드 + 큐)로, 제어 틱은 절대 블로킹하지
   않는 구조로 설계할 것.
4. 부하 조건(다른 프로세스, 노트북 절전)에서는 재측정 필요 — 스파이크 스크립트를
   대상 머신에서 실행하면 된다. Jetson 급 보드 측정은 [CLD-P53].
